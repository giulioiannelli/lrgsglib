Build System
============

This document describes the build system, Makefile structure, environment
configuration, and dependency management in lrgsglib.

Overview
--------

lrgsglib uses a Makefile-based build system that:

1. Compiles C/C++ extensions
2. Generates environment configuration files
3. Sets up conda environment
4. Creates required directories

Quick Reference
---------------

.. code-block:: bash

   # Full build (configuration + C compilation)
   make all

   # Build with submodule configuration
   make all LRGSG_LLIB=$(pwd)/.. CONDA_ENV_NAME=your_env

   # C compilation only
   make c-make

   # Clean and rebuild
   make clean && make all

   # Just configure paths
   make basic-config

   # Configure conda environment
   make conda-config

Makefile Structure
------------------

The main Makefile includes modular configuration files:

.. code-block:: text

   lrgsglib/
   ├── Makefile                  ← Main build file
   └── build/
       ├── lrgsg-paths.mk        ← Path definitions
       ├── cconfig.mk            ← C compiler configuration
       ├── cprogn.mk             ← C program definitions
       └── conda-config.mk       ← Conda environment setup

Main Makefile Targets
~~~~~~~~~~~~~~~~~~~~~

.. list-table::
   :header-rows: 1

   * - Target
     - Description
   * - ``all``
     - Full build: config + C compilation
   * - ``full-config``
     - ``basic-config`` + ``conda-config``
   * - ``basic-config``
     - ``path-config`` + ``env-config`` + ``create-dirs``
   * - ``c-make``
     - Compile all C programs
   * - ``clean``
     - Remove build artifacts

Path Configuration
------------------

Paths are defined in ``build/lrgsg-paths.mk``:

.. code-block:: make

   # Project root (lrgsglib directory)
   LRGSG_ROOT := $(shell pwd)

   # Library base directory (overridable)
   LRGSG_LLIB ?= $(LRGSG_ROOT)

   # Path definitions: NAME:dirname:PARENT
   LRGSG_PATHS := \
       BUILD:build:ROOT \
       DATA:data:LLIB \
       IPYNB:ipynb:LLIB \
       LOG:.log:LLIB \
       SRC:src:ROOT \
       TEST:test:ROOT \
       ...

**Key paths:**

- ``LRGSG_ROOT`` - Library root directory (lrgsglib/)
- ``LRGSG_LLIB`` - Outer project root (for submodule usage)
- ``LRGSG_DATA`` - Data storage directory
- ``LRGSG_IPYNB`` - Notebooks directory
- ``LRGSG_CCORE_BIN`` - Compiled C binaries

Standalone vs. Submodule Builds
~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

**Standalone usage** (lrgsglib is the main project):

.. code-block:: bash

   cd lrgsglib
   make all

All paths are relative to ``lrgsglib/``.

**Submodule usage** (lrgsglib inside another project):

.. code-block:: bash

   cd lrgsglib
   make all LRGSG_LLIB=$(pwd)/..

Paths for data, notebooks, and logs are relative to the outer project:

- ``data/`` → ``outer-project/data/``
- ``ipynb/`` → ``outer-project/ipynb/``
- ``.log/`` → ``outer-project/.log/``

Environment Configuration
-------------------------

The build system generates environment configuration files:

.env File
~~~~~~~~~

Generated by ``dotenv-file`` target:

.. code-block:: bash

   # .env file contents
   LRGSG_ROOT=/path/to/lrgsglib
   LRGSG_DATA=/path/to/data
   LRGSG_IPYNB=/path/to/ipynb
   LRGSG_LOG=/path/to/.log
   # Per-model binary directories are set via class attributes (_c_bin_dir)
   ...

Loaded automatically via ``python-dotenv`` in Python code.

lrgsg_env.py
~~~~~~~~~~~~

Generated Python configuration file:

.. code-block:: python

   # src/lrgsglib/config/lrgsg_env.py
   from pathlib import Path

   LRGSG_ROOT = Path("/path/to/lrgsglib")
   LRGSG_DATA = Path("/path/to/data")
   # Per-model binary paths accessed via Model._c_bin_dir class attribute
   # ...

Imported by the library to access paths.

C Compiler Configuration
------------------------

Defined in ``build/cconfig.mk``:

.. code-block:: make

   GCC = gcc
   CFLAGS = -O3 -march=native -Wall
   LMFLAG = -lm
   ALLFLAGS = $(CFLAGS) -DSFMT_MEXP=19937

**Compiler flags:**

- ``-O3`` - Maximum optimization
- ``-march=native`` - Optimize for current CPU
- ``-Wall`` - Enable all warnings
- ``-DSFMT_MEXP=19937`` - SFMT period parameter

C Program Definitions
---------------------

Defined in ``build/cprogn.mk``:

.. code-block:: make

   # Per-model program lists (unified binaries, runtime-selectable via flags),
   # each emitted into its own per-model bin/ directory
   PROGS_ISING := $(addprefix $(LRGSG_STATSYS_ISING_BIN)/, \
       IsingMetropolis IsingSimulatedAnnealing IsingParallelTempering)
   PROGS_VM    := $(addprefix $(LRGSG_STATSYS_VM_BIN)/, VoterSimulator)
   PROGS_CP    := $(addprefix $(LRGSG_STATSYS_CP_BIN)/, \
       ContactProcessEI ContactProcessSIR)
   # ... plus PROGS_KUR, PROGS_RD, PROGS_CODE, PROGS_POTTS, PROGS_XY,
   #     PROGS_HBERG, PROGS_MSPEC (continuous / vector dynamics)

   # Aggregate list of everything to build
   PROGS := $(PROGS_ISING) $(PROGS_VM) $(PROGS_CP) \
            $(PROGS_KUR) $(PROGS_RD) $(PROGS_CODE) \
            $(PROGS_POTTS) $(PROGS_XY) $(PROGS_HBERG) $(PROGS_MSPEC)

   # Shared source file paths
   PATH_SRCC_FILES = $(addprefix $(LRGSG_STATSYS_CCORE)/, \
       LRGSG_utils.c sfmtrng.c)
   PATH_SFMT_FILES = $(addprefix $(LRGSG_CCORE_SFMT)/, SFMT.c)

Simulator Build Rules
~~~~~~~~~~~~~~~~~~~~~~~

The Makefile defines an explicit per-model recipe for each simulator, linking
it against its pre-compiled object files:

.. code-block:: make

   # Unified Metropolis simulator
   $(LRGSG_STATSYS_ISING_BIN)/IsingMetropolis: \
           $(LRGSG_STATSYS_ISING)/IsingMetropolis.c $(OBJS_ISING)
       @printf "  [CC] IsingMetropolis\n"
       @$(GCC) $(ALLFLAGS) $(INC_ISING) -o $@ $< $(OBJS_ISING) $(LMFLAG)

   # Simulated Annealing variant (extra LRGSG_sa objects)
   $(LRGSG_STATSYS_ISING_BIN)/IsingSimulatedAnnealing: \
           $(LRGSG_STATSYS_ISING)/IsingSimulatedAnnealing.c $(OBJS_ISING_SA)
       @printf "  [CC] IsingSimulatedAnnealing\n"
       @$(GCC) $(ALLFLAGS) $(INC_ISING) -o $@ $< $(OBJS_ISING_SA) $(LMFLAG)

Conda Environment
-----------------

Configured in ``build/conda-config.mk`` and ``lrgsgenv.yml``:

.. code-block:: bash

   # Create environment from YAML
   conda env create -f lrgsgenv.yml

   # Activate
   conda activate lrgsgenv

   # Configure via Makefile
   make conda-config CONDA_ENV_NAME=lrgsgenv

**Key dependencies:**

- ``numpy``, ``scipy``, ``networkx`` - Core scientific computing
- ``matplotlib``, ``pandas`` - Data analysis
- ``pybind11`` - C++ bindings
- ``cupy`` - GPU acceleration (optional)
- ``graph-tool`` - Advanced graph algorithms (from conda)

Python Package Installation
---------------------------

After building, install the Python package:

.. code-block:: bash

   # Editable installation (development)
   pip install -e .

   # With optional dependencies
   pip install -e ".[dev,docs]"

Optional extras (from ``pyproject.toml``):

- ``dev`` - Development tools (pytest, black, isort, flake8, mypy)
- ``docs`` - Documentation tools (sphinx, pydata-sphinx-theme, sphinx-design,
  sphinx-autodoc-typehints, myst-parser, sphinx-copybutton, sphinxcontrib-bibtex,
  sphinx-autobuild)
- ``gpu`` - GPU acceleration (cupy)
- ``jupyter`` - Notebook tools (jupyter, ipykernel, ipywidgets)

Build Workflow
--------------

Complete build from scratch:

.. code-block:: bash

   # 1. Clone repository (with submodules)
   git clone --recursive https://github.com/giulioiannelli/lrgsglib
   cd lrgsglib

   # (if you cloned without --recursive)
   git submodule update --init --recursive

   # 2. Create conda environment
   conda env create -f lrgsgenv.yml
   conda activate lrgsgenv

   # 3. Build and install
   pip install -e .

   # 4. Verify
   pytest test/

The editable install drives the primary build system (CMake +
scikit-build-core, see ``CMakeLists.txt``), which compiles **both** the C
simulator executables **and** the pybind11 extension modules. No separate
``make all`` step is required.

The Makefile is a supported alternative for users who prefer it. Note that
``make all`` additionally runs ``env-config``, which pins absolute paths into
the generated configuration files:

.. code-block:: bash

   make all
   pip install -e .

For submodule usage, ``make`` can override the path layout so data, notebooks,
and logs land in the outer project:

.. code-block:: bash

   # Inside outer project
   cd lrgsglib
   make all LRGSG_LLIB=$(pwd)/.. CONDA_ENV_NAME=outer_env_name
   pip install -e .

Rebuilding After Changes
------------------------

**After modifying C code:**

.. code-block:: bash

   make c-make

**After modifying paths or adding new programs:**

.. code-block:: bash

   make clean && make all

**After pulling updates:**

.. code-block:: bash

   git pull
   make clean && make all
   pip install -e .

Directory Creation
------------------

The build system creates required directories:

.. code-block:: make

   DIRS_TO_MAKE = $(LRGSG_DATA) $(LRGSG_CCORE_BIN)

   create-dirs:
       @mkdir -p $(DIRS_TO_MAKE)

Troubleshooting
---------------

**"Command not found: gcc"**

Install GCC compiler:

.. code-block:: bash

   # Ubuntu/Debian
   sudo apt-get install build-essential

   # macOS
   xcode-select --install

**"Cannot find SFMT.h"**

Ensure submodules are initialized:

.. code-block:: bash

   git submodule init
   git submodule update

**"Permission denied" on scripts**

.. code-block:: bash

   make chmod-scripts

**Conda environment not found**

Create the environment first:

.. code-block:: bash

   conda env create -f lrgsgenv.yml
   conda activate lrgsgenv

**Path configuration issues**

Regenerate configuration:

.. code-block:: bash

   make clean
   rm .env src/lrgsglib/config/lrgsg_env.py
   make all

Debug Build
-----------

To see what the Makefile is doing:

.. code-block:: bash

   # Print paths
   make echo-paths

   # Dry run (show commands without executing)
   make -n c-make

   # Verbose compilation
   make c-make VERBOSE=1
